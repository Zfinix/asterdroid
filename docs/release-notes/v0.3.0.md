# Droid 0.3.0

*Your phone. Any agent.*

Experimental. `arm64-v8a` only. Aster Droid is now Droid. It no longer needs a Telegram bot or a paid key to start: a new phone is walked through a model and a place to talk, and the chat lives in the app. Any agent on your computer can drive the phone over MCP, and editors can talk to the agent on it over ACP.

---

## Update

Download `asterdroid-0.3.0.apk` from the [assets below](#assets) and open it on the phone, or:

```sh
adb install -r asterdroid-0.3.0.apk
```

It installs over 0.2.0 and keeps your settings, keys, sessions and memory. A phone that already has a key or a bot token skips onboarding and keeps talking where it did. The app is now called Droid on the home screen; the package is still `dev.aster.probe`.

## Start with no key

- **Onboarding.** A new phone goes through four steps, one at a time: a model, where to talk to it, the permissions, done. It comes back to the same step if Android restarts the app halfway, and Settings can run it again.
- **Try it free.** Free models through Kilo Gateway, with no account and no key. Droid picks the best free model that can see images and use tools. The free tier allows about 200 requests an hour, around 10 tasks. Those requests run on a trial service that keeps logs, so the app says to keep them away from banking, health and other private screens.
- **Your computer's model.** Droid looks for Ollama and LM Studio on the same Wi-Fi, lists their models, and uses the one you tap. If it finds none, it shows the command that makes each listen on the network.
- **Sign in or use a key.** OpenRouter signs in and hands back a key with nothing to copy. Any other provider, or any OpenAI-compatible address, takes a pasted key, which is tried before it is saved.

## Talk to it anywhere

- **Chat in the app.** The default once no bot token is set. Tool calls, plans and questions show as cards, and the agent can ask you to pick an answer. Replies arrive as notifications when the app is closed.
- **Telegram**, as before, now optional.
- **WhatsApp and iMessage through Photon.** One Photon project bridges both. Set Allowed people to the numbers that may ask.

## Setup links

A setup link or QR code from [droid.withaster.dev](https://droid.withaster.dev) carries a whole setup: the model, its key and the chat app. The settings ride in the part of the link a browser never sends to a server. Droid opens it straight from the camera, shows every change it would make, with keys cut to their last four characters, and writes nothing until you say yes. A link expires after 15 minutes and works once. A link that names a model address Droid does not know, or a relay of its own, says so in red or amber before you apply it.

## Connect a computer

**Connect a computer** in Settings turns each way in on and off:

- **Agents (MCP).** Claude Code, Codex, Cursor and other agents use the phone's screen, with the same receipts the built-in agent gets.
- **Editors (ACP).** Zed and JetBrains chat with the agent on the phone.
- **Over Wi-Fi.** Off by default, so both listen only on the phone and a USB cable reaches them through adb. On, they listen on the Wi-Fi address only, not on mobile data.

Each has its own 64-character key, made when you turn it on. The screen writes out the snippet for Claude Code, Codex, Cursor and Zed, with Copy carrying the whole key.

## The `@withaster/droid` CLI

```sh
npx @withaster/droid pair --adb               # phone on a USB cable
npx @withaster/droid pair --lan 192.168.1.20  # phone on this Wi-Fi or Tailscale
npx @withaster/droid setup all                # claude, codex, cursor, zed, jetbrains, vscode
```

`pair` checks each key against the phone before it saves it, in `~/.config/aster-droid/credentials.json` (0600). A bare `pair` uses adb when it sees exactly one phone, and otherwise says how to pair over Wi-Fi or USB. `setup` adds Droid to each client's config and never rewrites a file with comments in it. `aster-droid mcp` and `aster-droid acp` are the stdio bridges the clients launch, so the key stays out of their config files.

## Aster Relay is coming soon

Aster Relay will reach the phone from anywhere with one code, with no open port, adb or Tailscale. It is not open yet, so **Reach from anywhere** shows as coming soon and cannot be turned on, and a setup link cannot turn it on either. A relay you host yourself works now: set `ASTER_RELAY_URL` to its address and the switch comes back. [docs/RELAY.md](../RELAY.md#self-hosting) has the steps.

## Privacy

- Droid opts out of Android backup and device transfer, so `.env` with its keys never lands in a cloud backup or on another phone.
- Plain `http` is allowed only to addresses on your own network. A key is never sent to the internet without TLS.
- MCP and ACP keys are marked sensitive when copied, so Android 13 and later hide them in the clipboard preview.

## Known limits

- The in-app chat, Photon bridge and setup links are new in this release. Report a setup link that is refused when it should not be, or a chat reply that never arrives.
- Free models are rate-limited by the gateway, and a long task can run out of requests partway. Pick your computer's model or a key for heavy use.
- Over Tailscale, set Other agents' and Editors' address in settings to the phone's Tailscale address; Over Wi-Fi binds the Wi-Fi address only.
- Everything listed under 0.1.0 still applies: text input into views without an input connection, PIN and pattern locks, no start after reboot, `arm64-v8a` only.
