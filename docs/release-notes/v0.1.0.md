# Aster Droid 0.1.0

*Aster runs on an Android phone. The full agent, on the device, driven from Telegram.*

Experimental. `arm64-v8a` only. Building requires an Aster checkout beside this repository.

---

## The agent, not a client

`build-agent.sh` cross-compiles `aster-cli` for `aarch64-linux-android` and packages it as `libaster.so`. The agent process on the phone has the same tools, skills, prompts and review path as the terminal version. Sessions, memory and skills live on the device.

## Hands and eyes

An accessibility service reads and drives the screen.

- `capture()` walks the accessibility windows and returns numbered elements, skipping system bars and layout-only nodes, capped at 4000 nodes with 160-character lines.
- Gestures: `swipe`, `drag` with press/pause/move/pause/release, `pinch`, and `finger down|move|up` for held touches.
- Typing: `text` via `ACTION_SET_TEXT`, or `type` through a custom IME that draws no window.
- Fallbacks when the tree is useless: ML Kit OCR with numbered blocks, a labelled screenshot grid, colour-region targeting, and a thumbnail-diff path that reports changed rectangles.

## Receipts

Every action returns a dispatch receipt and the observed screen change:

```txt
receipt: posted ("System" via its row)
changed: +32 -30 pkg=com.android.settings after_ms=713
```

`posted` means the event was accepted. An empty diff returns `warning: nothing on screen changed; treat as not done`.

## Screen mirror

`/mirror` returns a browser URL that shows the phone and accepts input. MediaProjection feeds a hardware encoder directly; one capture serves all viewers and stays alive 30 minutes after the last leaves. Each viewer has its own writer thread and a 60-frame queue, and is dropped after five overflows. The wire format follows scrcpy; the Rust server converts to AVCC for WebCodecs.

## Telegram

A bot you own drives it. `/new`, `/stop`, `/retry`, `/queue`, `/mirror`, `/mode`, `/model`, `/effort`, `/status`, `/sessions`, `/resume`, `/memory`, `/remember`, `/skills`, `/learn`, `/checkins`, `/cron`.

## Known limits

- `arm64-v8a` only.
- The build needs an Aster checkout, `ANDROID_HOME` with platform 35 and an NDK, and `rust-src`.
- Broad permissions: accessibility, notification access, Do Not Disturb, battery exemption.
- Starts in `yolo` mode, since a phone has no terminal for approval prompts. It announces outbound actions rather than gating them. Change it per chat with `/mode`.
- `type` cannot reach a view that handles input without opening an input connection, such as some terminals. Read the field back to verify.
